# Suite vs MAX — 详细对比

## 一句话区别

| | Suite | MAX |
|------|-------|-----|
| **做什么** | "你的设计系统 AI 能用吗？" | "你的设计系统 AI 用得怎么样？" |
| **产出** | 评估报告 + 改善建议 | 组合规则引擎 + 场景推荐 + 持续优化 |
| **定位** | 诊断工具 | 数据治理基础设施 |

## 能力矩阵

| 能力维度 | Suite | MAX | 说明 |
|----------|-------|-----|------|
| AI 就绪度评估 | ✅ 完整 | ✅ 完整 | 多维度评分 + 定性报告 |
| 组件数据侦察 | ✅ | ✅ | 库结构分析 + 质量问题标记 |
| AI 生成代码审计 | ✅ | ✅ | 组件使用合规性审计 |
| 报告输出 | ✅ | ✅ | 多层转译，适配不同受众 |
| 组件组合关系定义 | — | ✅ | allowed_children / forbidden_children |
| 条件规则 | — | ✅ | 情境感知的组合判断 |
| 场景级组件推荐 | — | ✅ | 按业务场景匹配组件 |
| 语义插槽 | — | ✅ | 组件内部区域的角色定义 |
| 规则版本管理 | — | ✅ | 设计规范变更后规则同步 |
| 命名空间隔离 | — | ✅ | 多业务线独立规则管理 |
| 增量规则更新 | — | ✅ | 变更热加载，不全量刷新 |

## 适用场景

### Suite 适合

- 想了解当前设计系统的 AI 可用性水平
- 需要说服团队/管理层投入 AI 就绪化改造
- 在做工具选型，需要评估不同设计系统的差距

### MAX 适合

- 设计系统规模大（500+ 组件），AI 生成质量不稳定
- 多个业务线共用设计系统，需要精细化的规则管理
- 已经过了"要不要做 AI"的阶段，进入了"怎么把 AI 用准"的阶段
- 需要让 AI 理解的不只是单个组件，而是整个业务场景的组装方式

## 升级路径

```
Suite（评估诊断）
  │
  ├─ 产出：你的设计系统 AI 就绪度评分 + 盲点清单
  │
  ▼
MAX（组合推理引擎）
  │
  ├─ 输入：Suite 的评估结果 → 精准定位需要补充规则的组件
  │
  ├─ 新增：组合规则定义 + 场景推荐 + 持续规则管理
  │
  ▼
结果：AI 从"看到组件"进化为"理解组件间关系"
```
