# MAX 能力详情

## 1. 组件组合关系推理

**场景**：设计系统的 "Header" 组件允许哪些子组件？

**MAX 做的事**：
- 定义组件级别的 `allowed_children`（允许的子组件）和 `forbidden_children`（禁止的子组件）
- 支持条件规则（"允许 Button，但仅当父组件是 Dialog 的 Footer 区域时"）
- 支持语义插槽（"Header 左侧区域 → NavItem，右侧区域 → ActionGroup"）

**企业价值**：AI 生成的页面不再出现组件嵌套错误，交付质量从"需要验证"提升到"可直接评审"。

---

## 2. 场景级组件推荐

**场景**：设计师要做一个"数据看板"页面，哪些组件最合适？

**MAX 做的事**：
- 为每个业务场景维护组件推荐列表（按适用度和使用频率排序）
- 场景标签支持层级（"运营监控 → 设备监控 → 实时告警看板"）
- 场景切换时自动调整组件推荐策略

**企业价值**：从"设计师手动翻组件库"变成"按场景自动推荐"，页面搭建效率显著提升。

---

## 3. 企业级规则管理

**场景**：多个业务线各自的组件库，规则怎么管理？

**MAX 做的事**：
- 支持命名空间隔离（业务线A的规则 ≠ 业务线B的规则）
- 支持规则版本管理（设计规范 v2.0 的规则不会错误应用到 v1.0 的组件上）
- 支持增量更新（只同步变更的规则，不重新加载全量数据）

**企业价值**：大型组织可以按业务线独立管理组件规则，不影响全局一致性。

---

## 4. 与评估引擎协同

MAX 包含 Suite 的全部评估能力（AI 就绪度诊断、组件数据审计），并在评估结果的基础上：

- 自动识别"需要补充组合规则"的高优先级组件
- 提供规则建议模板（"当前组件缺失组合定义，建议至少定义 3 条规则"）
- 量化改善效果（"补齐规则后，AI 生成页面的组件合法性预计从 X 提升至 Y"）

**企业价值**：评估 → 诊断 → 修复 → 验证，形成闭环，不是看一次报告就结束。
